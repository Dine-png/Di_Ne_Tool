# Multi Dresser / Smart Toggle 수정 검토

## 사용 흐름

- 아바타 자식 오브젝트 우클릭 → `Di Ne > Smart Toggle`을 실행하면 그 오브젝트에만 Smart Toggle 컴포넌트가 붙는다. 멀티 드레서를 만들거나 등록하지 않는다. 해당 오브젝트를 선택해 메뉴 이름, Bool 이름, 기본 ON, 저장 여부, 아이콘, 메뉴 위치를 설정한다.
- Smart Toggle은 자신이 붙은 오브젝트의 활성 상태만 제어한다. 멀티 드레서 Inspector의 독립 토글 목록에는 표시하지 않는다. 기존 Smart Toggle의 직렬화된 메뉴 위치는 유지하며, 위치를 선택하면 새 메뉴 경로로 저장한다. 기존 Dresser 참조는 호환성을 위해 필드만 남기며 등록/동작에 사용하지 않는다.
- 멀티 드레서는 공통 설정 아래의 **옷장 / 독립 토글** 탭으로 목록을 분리한다. 독립 토글은 의상 목록 맨 아래로 스크롤하지 않고 바로 편집한다. 선택한 탭은 현재 Unity 세션에서 컴포넌트별로 기억하며, 탭 전환 시 입력 중인 지연 텍스트를 확정한 뒤 페이지를 바꾸고 진행 중인 미리보기를 복원한다. 아바타·FX·메뉴 설정과 자동 적용 안내는 공통으로 유지한다.
- 멀티 드레서의 **독립 토글** 탭에서 **독립 토글 추가**로 토글을 여러 개 만든다. 각 토글은 별도의 Bool와 메뉴 버튼을 갖는다. **함께 켜고 끌 오브젝트** 목록에는 여러 대상을 넣을 수 있으며, 하나의 Bool와 On/Off 애니메이션이 목록 전체를 동시에 제어한다.
- 각 토글의 **오브젝트를 여기에 드래그해 추가** 영역에 여러 오브젝트를 한 번에 넣는다. 빈 슬롯 추가와 선택한 오브젝트 추가 버튼은 제거했다. 드래그 영역은 표준 민트색, 흰색 14px 굵은 중앙 정렬 글씨와 최소 48px 높이를 사용하며 좁은 Inspector에서는 줄바꿈한다. 이 작업은 Smart Toggle 컴포넌트를 생성하지 않는다. 중복, 아바타 밖의 대상, 다른 토글/옷장에서 제어하는 대상은 건너뛰고 이유를 안내한다. 직접 직렬화된 잘못된 참조도 생성 시 검증하여 제외한다.
- 독립 토글 카드와 Smart Toggle 설정 제목 옆의 **미리보기**를 누르면 기본 ON 설정으로 미리보기를 시작하고, 표시되는 **ON / OFF**로 전환한다. 여러 대상은 함께 전환되며 기본 ON이나 저장된 파라미터 설정은 바뀌지 않는다. **종료**(Smart Toggle은 **미리보기 종료**), Inspector 닫기, 선택 변경, Undo/Redo, 씬 저장/닫기, 도메인 리로드, Play Mode 진입 시 각 대상의 시작 전 활성 상태로 복원한다. 다른 의상/토글 미리보기를 시작할 때도 이전 상태를 먼저 복원한다.
- 독립 토글 카드는 의상 항목과 같은 76×76 아이콘 썸네일을 왼쪽에 표시한다. 오른쪽에는 메뉴 이름, Bool 이름, 기본 ON/값 저장을 세 줄로 배치하고 메뉴 위치는 아래 전체 폭을 사용한다. 미리보기/종료 버튼은 76px, 삭제는 툴팁이 있는 24px × 버튼이다. 대상 수를 제목 옆에 표시하고 중복 자동 적용 안내를 정리했다.
- 메뉴 위치는 컴포넌트가 속한 아바타의 실제 Expression Menu를 기준으로 고정한다. 선택창에는 아바타 이름 단계를 생략하고 `최상단 메뉴`, `Multi Dresser`, `Multi Dresser › Main`처럼 내부 위치를 한 목록에 표시한다. `/`로 인한 Unity의 연속 하위 팝업을 제거했으며, 실제 메뉴 이름에 포함된 `/`도 표시할 때만 `／`로 바꾼다. 저장된 경로는 유지한다. 멀티 드레서의 옷장 이름도 추가하므로 아직 의상이 없는 옷장에도 토글을 배치할 수 있다.
- 같은 이름의 메뉴는 경로와 순번으로 구분한다. 이름에 `/`가 있어도 경로를 안전하게 저장한다. 순환 메뉴 참조를 방지하며, 메뉴/계층/Undo 변경 시에만 목록을 다시 수집한다. 사라진 메뉴는 재선택 항목으로 표시하며 임의 위치로 배치하지 않는다.
- Bool 이름은 생성 시 기본값을 채우고, 아바타의 Expression Parameters, FX, 다른 Smart Toggle, 독립 그룹 토글, 생성 전 옷장 이름과 중복 검사해 `_2`, `_3`를 붙인다. 직접 입력한 이름도 확정 시 검사한다. 빌드에서도 기존 Bool/Int/Float 설정을 덮어쓰지 않고 중복을 처리한다.
- 생성은 Play Mode/업로드용 임시 아바타에 적용한다. 독립 그룹과 Smart Toggle은 서로 다른 Animator 레이어 이름을 사용한다. 메뉴 경로의 원본 하위 메뉴는 복제하여 사용한다. 메뉴가 가득 차면 페이지를 만든다.
- Smart Toggle과 독립 토글 모두 별도 적용 버튼 없이 SDK 업로드 전처리에서 자동 적용된다. SDK 빌드 요청 단계에서 미리보기를 먼저 해제해 원래 상태의 아바타를 복제하고, Play Mode와 직접 전처리 진입에도 복원 호출을 둔다. 멀티 드레서 하단의 기존 자동 적용 안내를 사용하고, 기본 ON 체크박스 툴팁에 미리보기가 기본값을 변경하지 않는다는 설명을 제공한다. Smart Toggle은 자체 하단 안내를 유지한다.
- 의상 아이콘은 같은 이름의 PNG가 있으면 재사용한다. **아이콘 편집 / 아이콘 재생성 / 이름 바꿔 생성**은 높이 24px의 동일 너비 3개 버튼으로 한 행에 표시한다.

## 대기 상태 작업 감소

- Multi Cleaner의 매 Editor 업데이트 씬 검색을 제거하고 계층 변경 시 한 번 예약한다.
- Multi Dresser의 대상/메시/쉐이프키 수가 같으면 전체 이름 목록을 다시 동기화하지 않는다.
- GUIStyle 및 메뉴 선택 목록을 캐시하고, 변경 없는 EditorPrefs 쓰기를 줄였다.
- 새 에셋 배지의 Project Browser 검색은 초당 최대 4회로 제한했다.

## 검증

Unity 2022.3.22f1의 분리된 테스트 프로젝트:

```powershell
./Tests/MultiDresserPreview/Run-MultiDresserPreviewRegression.ps1 -UnityEditorPath 'E:/Unity/2022.3.22f1/Editor/Unity.exe' -ProjectName MultiDresserRequestedChanges
./Tests/MultiDresser/Run-MultiDresserRegression.ps1 -UnityEditorPath 'E:/Unity/2022.3.22f1/Editor/Unity.exe' -ProjectName MultiDresserRequestedAnimationRegression
```

미리보기/아이콘/토글/UI 테스트 17항목 통과. 기존 의상/FX/MMD 테스트 11항목도 앞선 변경에서 통과했다. 실제 Unity Animator에서 하나의 Bool로 두 오브젝트를 함께 껐다 켜는 clip sampling, 단독 Smart Toggle 우클릭 생성/중복 방지/Undo, 그룹 추가 Undo, 기존 Bool/Int 보존, 기존 중첩 메뉴/동명 메뉴/순환 참조/아직 생성하지 않은 옷장, 원본 하위 메뉴 보존, 3개 언어의 IMGUI Layout/Repaint와 대기 중 직렬화 데이터 보존을 검증한다.

YakGwa의 실제 SDK 참조로 Runtime/Editor를 별도 폴더에 컴파일한다. Unity 엔진 테스트는 SDK/자동 적용 콜백/NDMF/아이콘 캡처 일부를 대역으로 사용하므로 실제 VRChat 업로드, 사용자 아바타의 체감 프레임률과 캡처 이미지 품질은 별도로 확인해야 한다.

새 미리보기 검증은 혼합된 초기 활성 상태, 그룹 ON/OFF, 미리보기 소유 Inspector 교체·종료, Undo, 실제 씬 저장·재로드, 활성 미리보기의 3개 언어 반복 Layout/Repaint를 포함한다. 동기식 테스트 실행 중 지연되는 선택 변경은 등록된 Unity 이벤트 구독자를 호출해 연결과 복원을 검증한다. Prefab Stage 저장 훅은 소스와 실제 SDK 컴파일로 확인했으며, 실제 업로드와 Prefab 자동 저장 UI 조작은 실행하지 않았다.

높이 제한은 `Tests/MultiDresserPreview/ToggleLayoutMeasurement.cs`로 수정 전후를 측정했다. 폭 320/400/530/700px, 영어/한국어/일본어, 대상 0/2개, 미리보기 꺼짐/켜짐의 48가지 조합에서 독립 토글 영역 높이가 모두 62~86px 감소했다. 빈 대상의 미리보기 조합은 배치 측정용으로만 강제 활성화한다. 아이콘 확대 후 기존 17개 테스트와 실제 YakGwa SDK 컴파일도 통과했다.

탭 분리 후에도 동일한 17개 테스트와 실제 YakGwa SDK 컴파일을 통과했다. 탭 전환 시 그룹 미리보기 복원, 설정 보존, Inspector 재생성 시 선택한 탭 복원을 검증하고, 독립 토글 탭을 실제로 그려 3개 언어의 Layout/Repaint를 확인한다. 입력 확정은 Unity의 포커스 해제 처리 후 `delayCall`에서 페이지를 바꾸는 방식이며, 실제 키보드 입력 후 탭 클릭의 전체 이벤트 경로는 자동화하지 않았다.

## UI 표준 체크리스트 검토

- 기존 Di Ne 로고, DungGeunMo 36px 제목, 72px 아이콘, 중앙 12px 설명과 언어 툴바를 유지한다.
- 기존 컴포넌트 아이콘 GUID를 유지한다. 새 메뉴/편집 보조 클래스는 컴포넌트가 아니므로 컴포넌트 아이콘은 해당하지 않는다.
- 새 문구는 영어/한국어/일본어를 제공하고 `DiNeLang`을 공유한다.
- 주요 추가 버튼은 표준 민트 30px, 보조 버튼은 Unity 기본 스타일 24px이다. GUI 배경색은 즉시 복원한다.
- 옷장 / 독립 토글은 기존 표준 35px 민트 툴바를 공유한다. 독립 토글 탭은 GroupBox 안에, 개별 토글은 helpBox 카드에 배치한다. 각 카드 제목과 설명을 제공하며 두 목록을 한꺼번에 세로로 쌓지 않는다.
- 불필요한 브랜드/설정 팝업을 추가하지 않고 Bool 이름, 기본 상태, 저장 여부, 메뉴 위치, 대상 목록을 바로 편집한다.
- 기존 형식 팝업과 옷장 이름 직접 입력을 실제 이름을 인식하는 경로 선택창으로 교체한다.
- 대상 추가 결과와 충돌 이유를 카드 아래 안내하고, 자동 Play Mode/업로드 적용 상태 안내를 유지한다.
- 미리보기는 기존 제목 행의 24px 버튼을 사용하고 활성 상태와 ON/OFF 선택은 표준 민트로 표시한다. 미리보기 자체는 임시 동작이므로 Undo 기록 대신 원래 상태를 보관·복원하며, 설정 편집의 Undo/Prefab 처리와 분리한다. 씬 저장과 SDK 빌드 전에 임시 값을 복원한다.
- 편집은 SerializedProperty, 생성/여러 대상 추가는 Undo.RecordObject와 Prefab override 기록을 사용한다. 자동 갱신으로 토글 데이터를 변경하지 않는다.
- 기존 Multi Dresser/Lighting Designer의 시각 토큰과 구조를 비교하고 실제 IMGUI Layout/Repaint를 검증했다. 실행 중 YakGwa 화면의 스크린샷 비교는 수행하지 않았다.
